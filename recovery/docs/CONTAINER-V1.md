# RZ 单文件容器 v1

实现版本 `rz 0.8.0`。外层容器版本与内部 profile、加密套件独立编号。
容器 v1 只封装已有的 profile 5 字节，不增加压缩层，不改变纠错、加密、密钥或私有索引协议。
所有整数均为无符号小端，摘要为完整 32 字节 BLAKE3。

## 布局

```text
容器头[128]
manifest.rzm[b+32]
d000000.rzv[V] … d(K-1).rzv[V]
p000000.rzr[V] … p(M-1).rzr[V]
容器头副本[128]
```

K、M、b、V 分别是数据卷数、恢复卷数、bootstrap 长度、每卷物理大小。
每个成员的字节格式与旧版目录中的同名文件完全相同，详见 [profile 5](FORMAT-V5.md)。
总长 `T = 256 + b + 32 + (K+M)*V`。数据卷从列 0 起、恢复卷从列 K 起，
第 c 列偏移为 `128 + b + 32 + c*V`。没有可由归档指定的成员路径或任意偏移表。

## 128 字节容器头

| 偏移 | 字段 |
|---:|---|
| 0 | ASCII `RZCNT001`，8 字节 |
| 8 | 容器版本 u32 = 1 |
| 12 | K，u32 |
| 16 | M，u32 |
| 20 | 保留 u32 = 0 |
| 24 | 归档 UUID，16 字节 |
| 40 | b，u64 |
| 48 | V，u64 |
| 56 | T，u64 |
| 64 | 保留 32 字节，全零 |
| 96 | 前 96 字节的 BLAKE3 |

读取首先验证摘要，再验证 `1 ≤ M ≤ K ≤ 100`、`144 ≤ b ≤ 8192`、
`240+2*b+2*65568 ≤ V ≤ 2*MaxStream`、`(V-240-2*b) mod 65568 = 0`，
以及 T 的精确公式。所有算术在上述有界几何中完成，IO 使用 64 位偏移。
读取 bootstrap 后还须核对 UUID、K、M、b、V、T 与 profile 5 计算值完全一致。

首头损坏可使用文件末尾副本；末尾副本只有在其 T 等于实际文件大小时才接受。
首尾两份有效头冲突时拒绝。两份均无效时拒绝，不猜测或扫描未知布局。
尾部截断时可凭首头定位仍存在的数据，超出物理 EOF 的区域作为缺损记录处理。
缺少头副本或物理长度不匹配计为元数据损坏；`verify` 不会将其报告为完好。

## 读取、修复与发布

- 容器仅以普通文件、`O_NOFOLLOW` 打开；成员视图复用已打开的 inode，以 `pread` 随机读取。
- 每个成员视图有独立边界，不能将下一成员的字节误读为当前卷的尾部。
- 对目录归档使用同一 profile 5 解析、校验、恢复链；容器读取不解包、不写临时文件。
- 创建和修复使用私有暂存目录。组装按卷顺序、以 1 MiB 缓冲复制，逐卷删除已复制暂存成员。
- 最终容器重新打开并通过完整验证后，先同步，再原子且禁止覆盖地发布。失败和取消清理暂存数据。
- 使用独立密钥时 `.rzkey` 仍位于容器外，与原有先发布密钥、后发布归档的规则一致。

恢复保证以内部条带与卷为单位：只要容器头和必要启动副本仍可定位，每条带最多 M 个坏块可按原规则恢复。
该保证不涵盖整个容器丢失，也不涵盖两个容器头同时损坏。

## 兼容性

创建与修复默认输出容器。读取自动区分普通文件与旧版目录，无需额外选项。
`--directory` 让创建或修复输出旧版分卷目录，可用于分卷独立存放或旧版工具互操作。
`rz repair old-directory new.rz` 将旧目录重建为容器；`rz repair new.rz legacy --directory` 反向导出。
两个方向都验证结果、保留源归档和 UUID；原密码或独立密钥仍然有效。
