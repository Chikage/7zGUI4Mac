# RZ Profile 5：分页摘要索引与可恢复索引区

状态：实验格式；实现版本 `rz 0.7.0`。所有整数为无符号小端，摘要为完整 32 字节 BLAKE3。
Profile 1–4 的字节含义、内容上限和默认 CLI 行为保持不变。新格式只支持等大 K+M 卷，
`1 <= M <= K <= 100`。GUI 默认创建 Profile 5；CLI 显式使用 `--profile 5`，仅指定卷数仍创建 Profile 4。

## 限额与目标

- 原始内容与属性合计最多 **1 TiB**；最大压缩/加密逻辑流 `S = 1 TiB + floor(1 TiB/100)`。
- 保留 100,000 个条目、4096 字节路径、每条目 64 MiB 属性、16 MiB 私有目录索引限制。
  1 TiB 是内容上限，不承诺任意文件数量与路径分布都能达到该值。
- 内容帧仍最多 4 MiB、Zstd level 3；RS 块仍 64 KiB。私有目录沿用 `RZPRI003`，
  属性沿用 `RZMET001`，两种 AEAD 套件及 `.rzkey` 沿用现有协议。
- 原来驻留且在每卷重复的完整块摘要表改为 64 KiB 页；启动元数据最多 8 KiB，根表最多 1 MiB。
- 数据和索引分别按相同 K+M 编码。任意 M 整卷丢失，在剩余卷完整且至少一份启动元数据可定位时可恢复。
  对普通随机损坏，两类条带分别允许最多 M 个不可用记录；不将比例当成任意分布的全局损坏保证。

## 物理布局与几何

定义 `B=65536`、`R=B+32=65568`、逻辑内容流长度 `s>0`：

```
D = ceil(s / (K*B))                        数据条带数（每数据卷 D 块）
P = ceil(D*(K+M)*32 / B)                    摘要叶页数
root_size = 44 + 32*P
I = ceil((P*B + root_size) / (K*B))          索引条带数
```

所有卷名继续为 `d000000.rzv` / `p000000.rzr`，索引副本为 `manifest.rzm`。
每个数据或恢复卷完全等大，卷内顺序：

```
卷头[120] | bootstrap[b] | 数据记录[D*R] | 索引记录[I*R] | bootstrap[b] | 卷尾[120]
```

每个记录为 `块载荷[65536] || 局部摘要[32]`。数据块和索引块都在各自逻辑流尾部补零。
每卷大小 `240+2*b+(D+I)*R`。JSON 的 `dataBytes` / `payloadBytes` 只统计数据/恢复内容块，
不含索引；`metadataBytesPerVolume=240+2*b+32*D+I*R`，
`volumeSizeBytes=dataBytes/K+metadataBytesPerVolume`。`contentLimitBytes=1099511627776`。

卷头/尾沿用 120 字节结构，magic 分别为 `RZVOL005`、`RZEND005`：
magic[8]、profile u32=5、parity u32、UUID[16]、卷号 u32、保留 u32=0、
bootstrap长度 u64、载荷长度 u64=`(D+I)*R`、bootstrap摘要[32]、前88字节摘要[32]。
`manifest.rzm` 为 `bootstrap || BLAKE3(bootstrap)`。混入经过验证的其他 UUID、profile 或冲突启动副本必须拒绝。

## Bootstrap

不超过 8192 字节，字段顺序如下。所有几何字段须先与 `paged_layout` 的精确公式核对，再分配内存。

| 偏移 | 字段 |
|---:|---|
| 0 | `RZIDX005` [8] |
| 8 | UUID [16] |
| 24 | profile=5、块大小、帧大小、K、M，各 u32 |
| 44 | 内容逻辑流长度 s，u64 |
| 52 | D，u64 |
| 60 | I，u64 |
| 68 | P，u32 |
| 72 | root_size，u64 |
| 80 | 根表 BLAKE3 [32] |
| 112 | security flags u32：encrypted=1、metadata=2、keyfile=4 |
| 116 | 私有目录原始长度 u64 |
| 124 | 私有目录帧数 u32 |
| 128 | 每帧 offset u64、stored u32、plain u32 |

随后，加密归档写入与 Profile3 相同的套件号、KDF 参数、salt、nonce、可选 AES nonce、wrapped key、public MAC。
最后总是写入 `index_volume_hash_count u32 = K+M` 及 `K+M` 个索引卷整体摘要，先数据卷后恢复卷。
整体摘要为该卷索引区域所有 `payload || local_digest` 记录的连续 BLAKE3。

加密归档的 public MAC 沿用 `ArchiveKeys::manifest_mac`，输入是将 MAC 字段置零的**整个 bootstrap**，
因此同时认证根表摘要、索引卷摘要、几何、身份和密钥包装参数。不可使用旧公开索引的序列化器。
增加内容上限只放宽 Profile5 写入器的记录偏移上限；旧 profile 的创建与解析仍限制为 64 GiB。

## 摘要页、根表与索引保护

数据块摘要沿用 `block_hash_v2(UUID,stripe,column,payload)`，块号从0开始，列顺序为 K 数据列、M 恢复列。
每个数据记录尾部保存该摘要。把所有数据条带的 `(K+M)` 个摘要按条带顺序连接，切成 P 个 64 KiB 叶页，
最后一页补零。每个叶页计算完整 BLAKE3。

根表序列化为：

```
RZROOT05[8] || UUID[16] || K:u32 || M:u32 || D:u64 || P:u32 || leaf_hash[P][32]
```

索引逻辑流为 `全部叶页 || 根表`，根表起点为 `P*B`，尾部补零后按 K 数据列 + M 恢复列独立编码。
索引与内容区域都使用 Profile2 系统 Cauchy 矩阵、GF(256)/0x11d，不调用不同矩阵的旧 Profile1 模式。
索引记录局部摘要为：

```
BLAKE3("rz5-index-block" || UUID || stripe:u32 || column:u32 || payload[65536])
```

根表和叶页本身受 RS 保护，因此不存在“必须先读完整无损摘要表才能修复它”的循环依赖：
局部摘要先定位普通擦除并重建索引记录，再以 bootstrap 根摘要、叶页摘要核实重建结果。
内容块必须同时受已验证叶页中的预期摘要约束，不能只信任记录尾部可重算的局部摘要。

每卷索引区域整体摘要额外覆盖索引恢复块与尾部填充，避免攻击者同时修改索引载荷和局部摘要而绕过完整校验。
有普通擦除时先在内存重建并复算区域摘要；仍不匹配的索引列作为可疑列参与恢复。
修复结果必须重新从磁盘读取，验证所有整体摘要和分页认证链，成功后才发布。
对恶意自洽伪造不承诺所有可理论纠正的分布都能恢复；必须检测并拒绝未经认证的结果。

## 读取、资源和失败语义

- 列目录仅读取必要索引页；普通提取按需校验内容块，不先扫描全部恢复卷。
- 完整验证扫描所有内容/恢复记录和索引区域。数据卷按最多4路顺序IO扫描，解密/解压复用有界256 MiB池；
  创建时显式线程数同样约束复验，独立 verify/extract 默认自动调度。
- 根表至多1MiB，页缓存16页（1MiB），RS工作集至多200个块（12.5MiB）。
  大归档创建按需生成均匀几何，不分配逐块摘要或逐条带 CodingGroup 数组。
  完整扫描另有每数据条带2字节错误计数，1TiB最窄条带时约34MiB；索引、线程栈等不属于压缩池预算。
- 私有目录和内容解密仍使用 AEAD；临时磁盘不保存解密后的输入流。敏感内存异常路径清零。
- 创建使用直接暂存卷、回填头尾、fsync、重新打开完整复验，再禁止覆盖地原子发布。
  创建后的加密复验复用已有密钥，验证解密内容，不重复 Argon2id。
- 修复无需密钥；生成的密文仍须密码/密钥才能认证和提取。无凭据 verify 只证明存储校验通过，
  不提供来源认证。未加密归档的 BLAKE3 也不提供对主动攻击者的来源认证。
- 超过恢复预算、所有可定位启动副本失效、错误认证或非法布局必须失败；不发布部分结果。
  `.rzkey` 不在 RS 保护内；实际断电与介质故障仍需后续实机验证。

固定的第二个 RS 索引区域会增加小归档填充开销。该版本优先解决大归档索引扩展和索引可恢复性，
保留 Profile4 供已有读取器及对小归档兼容性有要求的调用者使用。

## 实现与验证入口

`paged_format.cpp`：有界bootstrap、几何、根表、域和卷头；`paged_create.cpp`：流式建页及编码；
`paged_archive.cpp`：页读取、认证、扫描、修复与提取。
`paged_format_test` 验证1TiB合成几何和旧上限，`paged_security_test` 验证自洽伪造与恢复，
`paginated_archive` 验证真实多页、缺卷、损坏、兼容默认值与取消；详见 [验证记录](VALIDATION.md)。
