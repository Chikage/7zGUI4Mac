# 独立恢复密钥文件（RZ profile 3）

GUI 的 RZ 保护方式默认选择“自动生成密钥文件”，默认加密算法为现有的
XChaCha20-Poly1305 + AES-256-GCM 双层套件。可显式选择标准套件或改用密码／不加密。
此模式不使用用户密码、空密码或内置固定密钥。

## 输出与使用

创建 `资料.rz` 时，在同目录独立输出 `资料.rzkey`。密钥不放进归档或恢复卷。
持有两者即可解密；同目录存放方便使用，但不保护整个目录被复制的情况。
需要保密时分开存放，并另行备份密钥。恢复卷能修复密文，不能替代丢失的密钥。

GUI 的浏览、验证、解压自动寻找同目录密钥。CLI 的 list、extract 默认自动寻找，
verify 默认只校验存储，须明确指定 `--auto-key-file` 或 `--key-file` 才认证内容。
先尝试同名 `.rzkey`，再搜索同目录的 `.rzkey` 文件（扩展名不区分大小写）。
匹配依据是归档 UUID 和密钥包装认证，而不是文件名；归档改名和修复后 UUID 不变，
原密钥仍可复用。损坏、错配、非普通文件和符号链接密钥均不自动接受。
自动搜索最多遍历 65,536 个目录项及 512 个候选密钥；超过时仍可手动选择。

未找到可用密钥时，浏览仅返回锁定的公开摘要；GUI 提示选择文件。
验证或解压缺少密钥返回退出码 6，不发布明文。手动选择支持不同文件名／扩展名和不同目录，
仅在本次会话保留文件 URL；不会把密钥字节写进偏好设置、命令行参数或日志。
自动解锁遇到损坏的私有索引时，返回目录需修复的状态，保留 GUI 修复入口。

```sh
rz create input 资料.rz --generate-key-file
rz list 资料.rz --json                       # 同目录匹配并自动解锁
rz extract 资料.rz output                    # 同目录匹配并自动解密
rz verify 资料.rz --auto-key-file             # 完整认证内容和属性
rz extract 资料.rz output --key-file /backup/资料.rzkey
rz list 资料.rz --json --no-auto-key-file     # 只读公开摘要
rz repair 资料.rz 已修复.rz                   # 不需要密钥，也不复制密钥
```

没有 AES 硬件支持时，可显式选择 `--encryption standard` 创建密钥文件模式；
双层归档的密文修复仍可进行。不会静默降级加密算法。

## 文件格式与密钥管理

密钥文件固定 88 字节：

```text
ASCII("RZKEY001")[8] || archive_uuid[16] || random_secret[32] || BLAKE3(previous_56_bytes)[32]
```

随机秘密为 CSPRNG 生成的 256 位值，每次创建均重新生成；它包装随机归档主密钥，
并非直接作为所有记录共用的 AES 密钥。文件摘要用于发现意外损坏，不是来源签名。
密钥文件格式、长度、摘要和 UUID 都要检查，之后仍须通过归档密钥包装、公开索引 MAC
及记录 AEAD 认证。输入仅以 O_NOFOLLOW 打开普通文件；文件长度严格限制为 88 字节。

profile 3 新增 security_flags bit2（值 4）表示独立密钥来源，且必须同时设置加密位。
算法套件编号不变，password_opslimit 和 password_memlimit 均为 0，读取器严格校验。
此标志被公开索引 MAC 认证，旧读取器按未知标志拒绝；旧密码归档的字节布局保持不变。

包装根密钥为 BLAKE2b-256：key=random_secret，message 为：

```text
ASCII("rz-keyfile-kek-v1") || archive_uuid[16] || salt[16]
```

盐仍随机生成，固定高熵密钥不运行 Argon2id。包装 AAD 沿用对应套件，
两个密码成本字段写 0，并在尾部增加 ASCII `rz-keyfile-v1`，绑定密钥来源。
套件 2 继续由该根密钥派生两层不同的包装子密钥；随机主密钥、记录子密钥、
nonce 和双层包装规则仍见 [ENCRYPTION-SUITE-2](ENCRYPTION-SUITE-2.md)。
密钥内存使用安全分配器，读写缓冲及摘要状态清零；序列化预留固定容量，避免扩容遗留秘密副本。

## 发布与失败处理

密钥先写入去除继承 ACL 的私有临时目录，权限 0600，写完 fsync。
归档存储验证完成后，使用独占硬链接先发布同目录密钥，再原子、禁止覆盖地发布归档。
GUI 外层暂存采用同样的顺序，避免取消时只保留归档而丢掉密钥。
已有目标（包含符号链接）不覆盖；正常失败和取消只回收本次输出，晚到的文件冲突也保留原文件。
真实断电或 SIGKILL 可能留下私有临时目录或孤立密钥，不承诺两个独立目录项完全原子提交；
发生“归档已发布但目录同步失败”时保留密钥，不能为了清理而使归档不可解密。

本格式仍为实验格式，未经过独立密码协议审计。
